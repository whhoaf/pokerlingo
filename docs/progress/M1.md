# Milestone 1 progress: engine, app shell, Area B

Status: all 15 tasks in `docs/PLAN.md` are done. `npm test`, `npm run typecheck` and `npm run build` pass. Nothing was pushed and `npm run deploy` was not run.

## What was built

**Engine** (`src/engine`, pure TypeScript, no DOM)

- `rng.ts`: mulberry32, plus `deriveSeed` for retries and per-skill streams.
- `cards.ts`: card parsing, deck, dealing without replacement, screen formatting, spoken names.
- `handEval.ts`: typed wrapper around pokersolver (hand name, comparison, ties). pokersolver's `compare` is a sort order, so the wrapper flips its sign.
- `outs.ts`: pokersolver brute-force outs, plus a fast rank and suit version that generators use to reject bad deals. A test checks the fast version against the brute force on 400 random hands.
- `odds.ts`: required equity, rule of 2 and 4, exact equity.
- `scheduler.ts`: ts-fsrs wrapper with the plan's parameters, rating mapping, Easy placement, map buckets, and retrievability ordering.
- `day.ts`: 4am day key, day start, streaks.
- `curriculum.ts`: skill registry checks, prerequisites, map states, next skill to introduce.
- `session.ts`: the session engine with an injectable clock (due ordering, retries, probes, explainer, practice, timer, early end) and `PracticeRun` for extra practice.

**Skills B1 to B9** (`src/skills/B`): generators, graders, explainers, worked examples and the two further-reading links. Every question is rebuilt from skill ID and seed. Outs come from pokersolver brute force. Prompts never name the draw.

**Storage** (`src/storage`): IndexedDB schema version 1 with the four stores from the plan, a repo, export, and a validating import that replaces every store in one transaction. A bad file is rejected before anything is written.

**App** (`src/app`): Install, Home (with the first-run welcome and the export banner), Session, Summary, SkillMap, SkillDetail, Practice and Settings screens, and the PlayingCard, Table, ChoiceInput, NumberInput, Feedback, Timer, Explainer and ConfirmDialog components. Export uses the Web Share API with a file where available, otherwise a download.

**Install and offline**: manifest, icons drawn by `scripts/make_icons.py`, `generateSW` service worker precaching every build asset, iOS meta tags, and the install screen for iOS Safari with "Continue in the browser".

**Visual check**: `scripts/screenshots.py` drives the built app in Chromium at 390 by 844, device scale factor 2. It saves about 65 screenshots to `screenshots/` (gitignored). I opened them and fixed what I found (see below).

Each B skill test runs 500 seeds. It checks no duplicate cards, that the question is the same when rebuilt from its seed, that the grader's answer matches an independent computation (pokersolver brute force for outs, `odds.ts` or a hand-written formula for prices), that a wrong answer grades as wrong, and that the worked example is correct. A writing-rules test fails if any source file, test or user-facing string contains an em dash or an en dash.

## Conflicts and deviations, with reasons

1. **New-skill cap: per session, not per day.** PRD F2 and F6 say "up to 2 per session" and "new skills per session". The plan says "introduced today" and "per-day cap". They conflict, so I followed the PRD: the cap counts skills introduced in the current session. Home shows "Done for today" after a finished session and offers "Start another session" as a secondary button. If the owner wants a hard daily cap, it is a small change in `Session.pickNext`.
2. **Retries are capped at 3 per skill per session.** The plan does not say what happens when a skill is missed again and again. In the screenshot run, an all-wrong player starved the rest of the queue. After 3 retries the skill is left due for the next session. Every attempt still updates FSRS.
3. **A zero-answer session does not count as finished** for the streak or the done state. Otherwise opening a session with nothing to do could farm the streak.
4. **A time-out during an introduction.** If the timer ends during the two probes, the skill is not recorded and its probes come again next time. If it ends after the explainer, the last practice answer sets the first rating, as the plan says.
5. **Both probe questions are always asked**, even if the first is wrong, as the PRD says "two questions".
6. **Skill titles are hidden while a question is on screen** (shown in the feedback), because titles such as "flush draw" would name the draw.
7. **B9 bet sizes** go down to 0.1 of the pot (the plan only fixes B7's range). With only 1/4 pot and above, a call is never right for most draws, so B9 would almost always be Fold. The 500-seed test requires 30 to 70 percent Call.
8. **No `@types/pokersolver` exists on npm.** Typings are in `src/types/pokersolver.d.ts`.
9. **Extra files not in the plan layout:** `src/skills/B/common.ts` and `draws.ts`, `src/app/format.ts`, `data.ts`, `backupStatus.ts`, `backupFile.ts`, `src/types/*.d.ts`, `tests/helpers/*`, `scripts/screenshots.py`. A welcome panel on Home replaces a separate welcome screen.
10. **Dependency versions** are the ones npm resolved on 25 October 2026, pinned exactly: Preact 11.0.2, ts-fsrs 5.4.2, pokersolver 2.1.4, idb 8.0.4, Vite 8.3.5, Vitest 5.0.5, TypeScript 7.0.2, vite-plugin-pwa 2.0.0. `@types/node` was added for the file-scan test.
11. **Practise** (verb) is used on the button, to match British spelling.

## Known gaps

- **Not tested on a real iPhone.** That is Milestone 5. In particular the Web Share path for export (headless Chromium takes the download path), the Add to Home Screen flow, `navigator.storage.persist()` and the iOS keyboard behaviour are untested.
- **Service worker updates** (a new deploy replacing an installed copy) are not tested. `autoUpdate` is configured but only the first-load offline case was checked.
- Areas A, C and D show "Coming in a later update" on the skill map. Their skills are Milestones 2 to 4.
- Answer time is logged but not shown anywhere.
- No focus management or screen reader testing beyond labels on cards, the timer and dialogs.
- Backups from a newer schema version are rejected. There is no migration code yet because version 1 is the only version.
- The explainer for each skill fits one phone screen only roughly. Some explainers with the worked example scroll on a small screen.
- `localStorage` and `sessionStorage` are not used for progress. `sessionStorage` only remembers "Continue in the browser" for the tab.
